# Backlog completion walkthrough

Use harmless, explicitly labelled test records in the correct college. Never use a real candidate's offer as a test fixture. Login, verification links, passwords and provider credentials remain owner-controlled.

1. **Profile:** Student → Profile → add an internship/employment entry → save → refresh. Upload a plain text-based PDF. Readiness keeps the documented weighted formula; experience does not secretly add a new factor.
2. **Drive description:** Recruiter → create drive → paste the description → review mentioned skills → choose actual requirements and targets → save. Negated/optional wording needs human review. No automatic eligibility decision is made from prose.
3. **Application:** Student → Opportunities → inspect eligibility, factors and explanation → apply. Recruiter → Applications → review current profile → record review/shortlist with a reason. The frozen submission stays separate from current evidence. Withdrawal/closure removes recruiter access to the current profile.
4. **Staff review:** Admin → Student directory → search the college student → Review profile. Admin → Drive review → choose a drive → Run explained matching → inspect factors and separate lexical evidence → promote/reject a controlled candidate with a reason. This override is audited and does not replace student application consent.
5. **Assessment evidence:** Admin → Assessments → record source, reference, date and original score/maximum. Keep evidence-only unless the result should explicitly contribute to scoring. Adopt a controlled result, inspect the student's factor provenance, then withdraw with a reason and check fallback. Rerun saved matching/support reports after changes.
6. **Scheduling:** Admin → Scheduling → choose an active, consented shortlisted candidate and drive → choose Interview or Assessment → enter round, venue, panel and time → check constraints → propose → approve with a reason. Assessment completion is separate from interview selection and cannot create an offer.
7. **Reminders:** On a future approved event within 24 hours, Admin → Drive review → run due reminders. Student → Notifications → refresh and inspect the event. Repeated checks do not duplicate the same event/window key. Unattended sweeps require REMINDER_COLLEGE_IDS; free-service sleep can delay them.
8. **Drive closure:** Recruiter or Admin → drive controls → close with a reason. Verify new applications, matching runs and new scheduling proposals are refused; historical records remain readable. Reopen with a reason if needed.
9. **Offer and communication:** Follow docs/LIVE-ACCEPTANCE.md for a targeted announcement/read receipt and harmless private PDF upload, human review, separate issuance and owning-student download. Offer milestones remain distinct.
10. **Analytics:** Admin → Overview → inspect the outcome funnel/reasons with synthetic records included and excluded. Drive review → recorded demand shows open-drive skill counts and scoped lifecycle records; this is descriptive, not a labour-market forecast.
11. **Account controls:** Test owned export and sign-out-everywhere with a disposable account. Read the privacy notice before submitting a deletion request. Administrative restriction is separate from permanent erasure. Permanent deletion requires the reviewed retention/backup process in docs/ERASURE-EXECUTION.md and explicit approval; it is not a demo button.

Record what was actually observed. Passing local tests or loading a deployed control does not prove inbox receipt, an authenticated live workflow, independent fairness or synchronized database migration.
